# 网页全文翻译与请求调度（0.16.0）

调查与实现日期：2026-10-02 至 2026-10-03。

## 使用与范围

在网页点击扩展图标开启伴读，右下角「翻译全文」按段落显示中文对照。「还原原文」移除译文但保留当前页面已完成结果，再次开启可复用。提供暂停 / 继续；失败或限流时停止新的调度，不自动重试，已有译文保留。

标题、正文、列表、表格单元格，以及以 div / ARIA 列表项构成的正文复用现有提取器。排除导航、侧栏、页眉页脚、广告、编辑框、代码块和隐藏内容。优先 article / main，当前屏幕优先；页面动态新增正文和原文改变后重新提取并拒绝过期译文。每个原文节点保留其身份、事件与链接，译文使用 textContent 插入单独节点，不执行模型返回的 HTML。译文、控件均标记 data-easy-learn，正文扫描忽略这些节点及其插入 / 删除事件，避免自我触发。

翻译只在显式点击后请求模型；使用用户现有连接、模型和请求参数，发送正文片段、页面标题和章节标题。每段超过 2000 个字符会切片，避免单段长生成阻塞；中文按原片段顺序显示，完成进度仍按原段落计数。内容仅在当前页面内保存，不增加持久化文章或遥测。

网页结构识别是启发式：不读取跨域 iframe、封闭 Shadow DOM、图片文字或原生 PDF 画布。非语义布局中同时含直接文本和嵌套块的容器仍可能漏掉直接文本。PDF 全文双语、OCR、译文中的富文本重建及专业术语一致性不在本次范围。

## 复用调研与许可

- [Immersive Translate FAQ](https://immersivetranslate.com/docs/faq/) 描述正文识别与双语阅读，采用原文旁保留译文的阅读形式。
- [KISS Translator](https://github.com/fishjar/kiss-translator) 提供双语段落、富文本保留、聚合批次及流式输出等成熟功能。本次复用 Easy Learn 自有提取器、模型适配与队列，不引入第二套提供商协议。KISS 使用 GPL-3.0，本次仅参考公开功能与问题，未复制其代码；现有依赖与许可保持不变。
- [Immersive Translate issue #4082](https://github.com/immersive-translate/immersive-translate/issues/4082) 报告 GitHub 议题页面无法翻译。本地增加 div / ARIA 列表项的叶子块识别，并以合成页面覆盖；不声称已适配所有 GitHub 页面。
- [KISS PR #648](https://github.com/fishjar/kiss-translator/pull/648) 处理切换译文时的阅读位置。本地以原文段落为锚点，保留窗口 / 内部滚动容器位置，不采用源项目代码。

这些仓库和 issue 证明相关功能及用户需求，不能据 stars 推断活跃用户数量。

## 调度与取消边界

`src/core/reading-defaults.ts` 统一后台、内容脚本、扩展设置与独立工作台的默认值：6 路请求、每批 8 个候选，上限 12 路。存储中的明确设置优先，不以新版默认覆盖。提高并发减少整体等待，增加批次减少生词请求轮次；没有测量上游 TPS，不保证单条生成变快。

全文翻译复用现有 explain / translate 的最小输出协议和缓存，正文请求带 pageTranslation 标记。内容脚本只可用该标记发起无 concept、history、question、answer、goal 的翻译，其他特权操作仍限扩展界面。后台总队列的优先级为主动操作 100、全文翻译 10、自动注释 0，运行中的请求不抢占。

翻译取消以实际 sender 的文档 scope 为边界，只取消该文档的翻译，不影响生词分析、其他标签页或学习面板。页面端的取消 Promise 在快速暂停 / 继续之间串行，取消完成前不发新请求；epoch 和原文快照拒绝旧结果。关闭伴读仍通过既有 STOP / disconnect 清理全部文档请求。

## 已验证的发现与回归

1. 原注释观察器只检查 mutation.target，无法识别插在段落后的自有译文，会导致重复扫描。现在两个观察器共用 isExtensionMutation，检查目标及全部增删节点。
2. 单纯逐条还原缓存译文会不断更换可见锚点，在内层滚动区域产生位置偏移。同步显示缓存时使用同一原文锚点，祖先滚动裁剪参与可见性判断；真实 Chromium 回归禁用原生 overflow-anchor 后仍保持原文位置。
3. 正文过滤原本只检查行内样式，遗漏祖先 / 样式表隐藏内容。现在读取实际计算样式，测试涵盖 class 隐藏的正文与包裹在 div 中的 pre。
4. 独立审查发现，请求在读取设置和验证权限期间尚未登记取消控制器，会在用户暂停后仍发起模型调用。现在先登记控制器，在异步准备后及真正调用模型前复查取消状态；延迟设置读取的测试先失败后通过。
5. 动态页面移动原文或移除译文时，内容相同不代表位置仍正确。缓存译文也检查连接与邻接关系，修复位置而不重复调用模型；观察器保留这种外部移除的修复例外。段落重排回归先失败后通过。
6. 优先级测试原本隐含默认两路，默认提高后不再产生排队。测试显式设置两路来验证排序，同时另测默认六路与上限十二路。

验证入口：`pnpm test`、`pnpm build`、`pnpm build:workbench`、WSL 缓存 Chromium 的 `pnpm test:e2e`。测试只使用公共 / 合成正文与本机 mock；覆盖源 DOM / 链接、动态新增、长段切片、过期结果、限流暂停 / 手动恢复、缓存还原、内部滚动位置、文档隔离取消及已保存设置。最终验证：184 项单元测试、60 项真实 Chromium 浏览器回归全部通过；`pnpm build` 和 `pnpm build:workbench` 通过，`pnpm package:extension` 生成 0.16.0 ZIP，根目录结构、许可文件及 SHA-256 校验通过。独立审查的两个问题修复后复审未发现新的重要缺陷；随后仅调整浏览器测试的设置消息入口并补充文档。测试设置由真实扩展设置页发送，后台 worker 不作为自己消息的接收入口。模拟服务每批固定延迟 300ms 时，48 个远程候选共 6 批、峰值并发 6，总完成时间约 447ms（单纯串行延迟为 1800ms）；这是本机 mock 调度证据，不代表真实模型 TPS。仓库未配置或安装 formatter / linter，本次保持现有源码布局，对新增模块使用清晰排版；类型检查通过项目构建入口执行。

## 2026-10-03：PyTorch 页面报旧权限提示

用户翻译 [PyTorch Tensors 教程](https://docs.pytorch.org/tutorials/beginner/basics/tensorqs_tutorial.html) 时报告「当前页面只能发起正文难点分析和整页测验」。逐字对比确认，该文本存在于 0.15.0 的后台；当前源码、0.16.0 的 `dist/background.js` 与对应扩展 ZIP 均允许带 pageTranslation 标记的窄范围翻译，没有这句旧提示。

真实 Chromium 采用两个隔离的临时扩展 / 用户目录验证：使用官方教程的公开 HTML，在原 URL 上本地回放，阻止其他外部网页资源，模型只连接本机 mock，不使用用户配置或密钥。将历史提交 `b6840ed` 的后台与当前内容脚本组合时，复现 0/41 段、旧权限提示、模型请求 0 次；当前后台完成 41/41 段，模型请求 41 次，27 个代码块及原文不变。历史后台单独使用现有 Vite 编译，验证的是旧权限判断，不声称模拟了整个历史发行环境。未验证真实模型翻译质量与用户实际加载路径。

因此该提示定位到运行中的旧后台，不是 PyTorch 页面或上游模型权限。开发者重新生成 dist 只更新磁盘文件，不会使浏览器中的已加载扩展后台立刻更新。页面脚本和后台来自不同加载时刻时，界面也可能已经出现「翻译全文」，后台却仍然拒绝新操作；不能据按钮是否存在判断后台版本。

处理步骤：在 Chrome / Edge 扩展管理页确认 Easy Learn 的版本及已加载路径；加载本项目的 dist 时应指向当前生成目录，点击扩展的「重新加载」，再刷新原文章并重新开启伴读。若路径错误，改为加载当前 dist 或最新 ZIP 的解压目录。不要为了绕过旧版本错误扩大内容脚本权限。实际用户浏览器的重新加载由用户操作，不自动重载其其他阅读页面或清除已保存配置。
