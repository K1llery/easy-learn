# 阅读工作台交互改进（2026-10-03）

长文目录需要快速定位，生词本也需要在积累之后继续可用。本次在现有工作台增加目录标题搜索、定位当前章节、顶部章节位置与切换按钮、专注阅读，以及生词本的搜索和组合筛选。

## 使用

- 在目录上方输入标题关键词，支持忽略大小写、前后空格与全半角差异。搜索只筛选目录标题；点击结果仍跳到原文的真实章节。点击“定位当前章节”会清除搜索并把键盘焦点带回当前目录项。
- 顶部位置条表示当前章节或阅读片段的序号，不表示已读比例或学习掌握度。PDF 原有物理页码控件继续独立使用。
- 点击顶栏“专注阅读”，收起目录、字号与词汇基础设置、常驻释义提示。伴读启停、章节切换、划词学习、PDF 工具仍可用。悬停或聚焦单词时释义作为浮层出现。点击“退出专注”或按 Esc 恢复；编辑文本、打开设置/生词本/选段学习时 Esc 不接管输入。换文件开始普通阅读。
- 生词本可以搜索单词、中文释义、语境说明、缩写全称与歧义说明，并组合语言和学习状态筛选。导出仍包含全部“学习中”词汇，不受当前筛选影响。删除当前语言的最后一条记录后仍显示该语言筛选，并提供“清除筛选”。
- 短暂淡入只用于欢迎页、生词本和选段学习面板。系统开启“减少动态效果”后，工作台停用动画与过渡，包括已有加载指示和 PDF 目录反馈动画。

这些交互仅使用本机现有数据；搜索、切换专注、定位目录、筛选和导出均不发起模型请求。主动开启伴读和选段学习仍按原有规则调用模型。

## 复用与实现边界

检查现有 React、PDF.js viewer 和词汇模块后，没有发现需要新依赖的能力缺口。目录和生词本显示分别移入 `ReaderDirectory`、`ReaderVocabulary`；文档导入、PDF 所有权、伴读调度、存储键、词汇格式与 Anki 导出继续由原有模块负责。专注模式通过 CSS 切换布局，原文和 PDF viewer 保持挂载，保留原生批注编辑状态。

参考 [Readest 阅读界面和目录说明](https://www.readest.com/docs/reading) 的按需控件、章节定位设计；[Readest #3124](https://github.com/readest/readest/issues/3124) 展示了自动把目录拉回当前章会干扰目录浏览的问题。因此这里仅在用户明确点击“定位当前章节”时滚动目录，不在搜索、模型释义更新或章节观察事件中自动回滚搜索。

Readest 使用 [AGPL-3.0](https://github.com/readest/readest/blob/main/LICENSE)，本次仅参考公开的产品行为和故障场景，没有复制其代码、图标或数据。实现复用本项目已有 React（MIT）和 PDF.js（Apache-2.0），不引入新的代码或数据许可证。

## 验证

使用公开合成文字、30 节 Markdown、含图表的合成 PDF、本机模拟模型服务和 Linux Chromium。新增浏览器流程覆盖：搜索后原始章节索引与阅读位置恢复、定位当前目录的键盘焦点、跨文档清空搜索、专注切换保留原文 DOM、输入与面板的 Esc 边界、PDF viewer 与批注/导出保留、生词本组合筛选与全量导出、390px 深色布局及减少动画。

`pnpm test` 的 174 项单元测试、`pnpm build`、`pnpm build:workbench` 通过。浏览器回归的 34 项扩展流程通过；工作台全量重跑 28 项通过，审查修复后的生词本定向用例也通过。

独立只读审查发现：在活动筛选下删除整个词库最后一条记录会失去“清除筛选”入口。已修复空状态、补充删除全部记录与重置三项条件的流程，并通过独立复核。旧画笔流程的鼠标绘制坐标受新增顶部导航影响，现先将 PDF 绘图区滚到视口，再执行真实鼠标绘制。

未使用个人模型凭据，未新增真实上游模型效果或学习效果的验证。
